# Alpha 2.7.3 — Adaptive inference policy (`2.7.3+55`)

Implemented in source; Flutter/Dart CI, Android ARM64 compilation, and physical-device acceptance remain required.

- Add a deterministic advisory policy that selects a candidate context from the supported 512/1024/2048/4096-token choices using a fresh GGUF inspection, current available RAM, the stored Balanced/Performance/Unrestricted resource mode, and the Alpha 2.7.2 model-fit estimate.
- Balanced mode considers contexts up to 2048 tokens and prefers the largest candidate whose recommended planning envelope fits. Performance considers the full supported context range. When RAM telemetry is unavailable, the policy does not claim a fit and falls back to a conservative/default choice. Unrestricted always keeps the largest model-supported context, even when the current estimate says RAM is insufficient; the insufficient status and warning remain visible and the user must explicitly acknowledge the estimate before the readiness check.
- Recommend CPU threads from logical cores, with the existing native ABI ceiling of eight threads. Balanced starts at a conservative fraction (maximum four); Performance and Unrestricted can use up to the engine ceiling.
- In Balanced/Performance modes, lower suggested thread counts under high CPU utilization, severe/critical thermal status, or a critically low battery while not charging. Unrestricted does not silently throttle; it reports thermal/load/battery warnings instead.
- Add a review dialog with context choices, a 1–8 CPU-thread override, reasons and warnings. Nothing is applied until the user confirms. Insufficient-memory estimates require a second explicit acknowledgement; the native loader's live memory preflight remains authoritative.
- Pass selected context/thread values into `ModelRuntimeManager.prepare` and `switchTo`; preserve the selected thread count through the load lifecycle and restore the previous model with its previous thread count if a switch fails. A fresh GGUF scan is authoritative over the model catalogue; if the fresh scan omits context metadata, the manager does not reuse a stale cached context limit.
- Permit explicit reloading of the currently active model when the user chooses different runtime settings. Selecting the same active context/thread values does not trigger an unnecessary reload.
- Do not change SQLite schema, resource-mode persistence, Rust ABI, GGUF metadata, or native loader limits. This milestone only selects the context/thread parameters already supported by the engine.
- Add deterministic Dart tests for resource modes, context selection, thermal/CPU/battery behaviour, unrestricted warnings, runtime override validation, active-model reconfiguration and restoration after failed switching, plus Python source-contract checks.

Known limitations: recommendations are advisory, and CPU utilisation/thermal/battery samples are snapshots rather than continuous telemetry. No GPU selection, automatic background changes, dynamic context resizing during an active session, model-specific batch-size tuning, or measurement-based learned policy is included. Physical-device tests must validate that thread choices are stable and useful across Android hardware.
