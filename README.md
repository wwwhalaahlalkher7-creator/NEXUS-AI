# NEXUS AI — Alpha 0.8 GGUF metadata inspection

NEXUS AI is a local-first, multi-device AI platform. This repository is the **first source foundation**, not a finished AI runtime.

## Current scope
- Flutter mobile application shell (Arabic RTL by default; English-ready structure).
- Rust workspace with a small, testable core library.
- Agent domain model and in-memory Rust registry foundation.
- SQLite-backed local agent repository in Flutter (create/list/get/update/delete).
- Flutter-to-Rust runtime diagnostics and bounded GGUF header and metadata inspection through generated Flutter Rust Bridge bindings.
- SQLite-backed model metadata plus private local GGUF import and metadata validation; imported models are not loaded or executed.
- Architecture and development documentation.

## Not included yet
- llama.cpp inference integration, token generation, model downloads, and execution.
- Generated Flutter ↔ Rust bindings and native Android integration are generated by the CI workflow; they are not committed as hand-written source.
- Device discovery, pairing, networking, distributed scheduling.

The deferred capabilities above are intentionally separated from local model import so each layer can be validated independently.

## Requirements
- Flutter stable SDK
- Dart SDK bundled with Flutter
- Rust stable toolchain (`rustup`, `cargo`)
- Android SDK/NDK for Android builds

## Bootstrap
The repository is a single Flutter project at its root (`pubspec.yaml`, `lib/`, and `test/`). The `flutter_rust_bridge.yaml` configuration is also at the root.

Run from the repository root:

```bash
bash scripts/bootstrap.sh
```

The script creates the missing Android platform folder using Flutter, fetches Dart packages, and checks the Rust workspace. It does not install a model, configure cloud services, or deploy anything.

Then:

```bash
flutter run
```

For Rust checks:

```bash
cargo fmt --all -- --check
cargo test --workspace
```

## Product principles
1. Local-first; network is optional.
2. No fake AI, fake telemetry, or fabricated resource measurements.
3. Every device is an independently useful node.
4. Start by distributing agent tasks; distributed tensor inference is a later research phase.
5. Sensitive actions require explicit user approval.
6. The LLM is never the authority for permissions or security policy.

## GitHub Actions and APK
On every push and pull request, `.github/workflows/ci.yml` runs:
1. Rust formatting, tests, and Clippy.
2. Flutter dependency resolution, Dart formatting, analysis, and widget/unit tests.
3. Flutter Rust Bridge integration and code generation.
4. Android scaffold generation and a debug ARM64 APK build.

Open the repository's **Actions** tab, select the successful workflow run, and download
the `nexus-android-debug-apk` artifact. This is a debug APK for device testing, not a
signed Play Store release. The workflow does not deploy or modify any backend or website.
